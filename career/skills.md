# Skills

I started with embedded systems and later moved into user-facing software, scientific computing, platform operations, AI infrastructure, and technical leadership. The sections below show how and where I have applied each capability.

## Systems software and embedded foundations

I work across the hardware-software boundary: device communication, interrupt-driven control, sensor processing, Linux interfaces, and board enablement. Early work combined STM32 firmware and orientation estimation, wireless data transfer, and analysis tooling. I then developed reusable C++ communication components for AVR and STM32 before moving into Linux GPIO, PWM, bus integration, kernel fixes, and upstream open-source contributions.

**Represented in:** [engineering internship](experience.md#mechatronics-laboratory-at-hanyang-university), [freelance engineering](experience.md#freelance), [Linux systems engineering](experience.md#hardkernel), and [undergraduate capstone](education.md#undergraduate-capstone).

## Device-facing product and application engineering

I turn device and operating-system capabilities into software that people can operate. Public examples include a Flutter/MQTT remote controller, a PySide2 and RS-232 desktop controller, and Linux Flutter plugins for I2C, UART, and GPIO.

**Represented in:** [freelance product and control-software work](experience.md#freelance).

## Scientific software and research enablement

I make research code easier to install, execute, extend, and hand over. This has included organizing scientific Python programs into reusable command-line workflows, creating integration patterns for later researcher-developed tools, and connecting research software and models to shared services and calculation pipelines. The emphasis is on converting exploratory implementations into maintainable engineering interfaces without obscuring the underlying scientific work.

**Represented in:** [scientific-software engineering and platform work](experience.md#hits).

## Drug-discovery SaaS and full-stack engineering

I build scientific SaaS products across authentication, backend, frontend, and platform boundaries. At HITS, I led the development of an AI drug-discovery SaaS product that grew from internal scientific workflows. I worked across its authentication gateway, backend services, and frontend. My hands-on work focused primarily on DevOps and backend development, with partial frontend support.

**Represented in:** [lead software engineering and SaaS product development](experience.md#hits-lead-software-engineer).

## Platform engineering and reliability

I build repeatable paths for deploying and operating software. My work has covered Kubernetes lifecycle management, infrastructure as code, GitOps, CI/CD, observability, identity and access, migrations, troubleshooting, and operational documentation. In on-premises environments, I have worked with AMD Instinct MI250, MI300X, MI308X, and MI355X accelerators, Ceph storage clusters, and Layer 2 and Layer 7 load balancing with ARP- and BGP-based configurations. This capability grew from shared infrastructure for scientific software into sustained platform operations, where configuration, automation, and documentation preserve knowledge and reduce one-off intervention.

**Represented in:** [lead software engineering](experience.md#hits-lead-software-engineer), [DevOps engineering](experience.md#moreh-devops-engineer), and [DevOps team leadership](experience.md#moreh-devops-team-lead).

## AI and ML runtime engineering

I work on the engineering boundary between models and the systems that run them. Earlier public work included maintaining and extending a TensorFlow 2 YOLOv4 fork, including TFLite-related changes. Later work broadened into complex software systems for distributed inference. My current implementation focus includes a Rust-based AI inference gateway and Kubernetes operators in Go, alongside inference API compatibility, request routing, deployment workflows, observability, and conformance validation. The emphasis is on making model execution deployable, operable, and testable.

**Represented in:** [freelance applied ML experimentation](experience.md#freelance), [lead software engineering](experience.md#hits-lead-software-engineer), and [technical and product leadership](experience.md#moreh-product-team-lead).

## Technical and product leadership

I combine hands-on engineering with coordination across systems and teams. Demonstrated practice includes shaping work before implementation, using design documentation and code review to improve shared understanding, coordinating platform changes, setting cross-component priorities and sequencing, and translating product or ecosystem signals into scoped work and validation plans. My leadership scope has expanded from technical execution to operational coordination and product-level decision-making while preserving clear boundaries for component ownership and final code review.

**Represented in:** [lead software engineering](experience.md#hits-lead-software-engineer), [DevOps team leadership](experience.md#moreh-devops-team-lead), and [technical and product leadership](experience.md#moreh-product-team-lead).
